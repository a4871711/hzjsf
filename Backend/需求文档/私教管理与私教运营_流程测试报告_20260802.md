## 1. 测试结论

1. 私教管理和私教运营菜单均能打开，主要列表、筛选、详情、表单必填校验可用。
2. 私教商品导出按钮可用，页面提示 `导出成功`。
3. 教练代约课空表单校验可用；教练、会员搜索候选项可加载。
4. 现有测试预约点击“完成”后，页面提示 `核销成功`，预约从“已预约”变为“已完成”。此前的 `Unknown column 'coach_id' in 'field list'` 已通过 Flyway 迁移补齐字段并验证通过。
5. 当前测试数据存在两个会影响结算报表的配置问题：
   - 预约门店 `store_id=82` 在 `store` 主表中找不到，收入报表异常页提示“完成记录缺少门店”。
   - 教练分成规则 `id=999923` 绑定门店 `87`，但教练 `id=1` 当前可用门店关系为 `79,80,81,82,83,85`，规则门店不在教练可用范围内，按课时提成规则无法命中当前预约门店 `82`。
6. 收入报表明细能显示教练、课程和订单号，但正式汇总金额为 `¥0.00`，异常页把该记录分流；这与测试订单实付金额为 `0`、门店关联缺失及规则不匹配共同有关，不能单凭页面判断为前端金额计算错误。

## 4. 数据和配置问题

### P1：完成记录的门店无法关联主表

- 复现：打开“私教运营 → 私教收入报表 → 异常数据”。
- 页面实际：显示订单 `PTTEST20260802124521232575`，门店 ID `82`，异常原因 `完成记录缺少门店`。
- SQL 证据：预约 `pt_private_appointment.store_id=82`，但 `store.storeId=82` 不存在；因此 `LEFT JOIN store` 得到空门店名称。
- 影响：门店报表显示 `-`，收入记录被异常分流，无法按门店正常汇总。
- 建议：先确认门店主数据是否被删除、测试数据是否使用了旧门店 ID，再决定补数据还是修正预约/商品关联；不要直接改报表 SQL 掩盖主数据问题。

### P1：教练分成规则门店范围不一致

- 当前规则：`pt_coach_fee_rule.id=999923`，教练 `1`，商品 `1`，门店 `87`，按课时提成比例 `20%`。
- 教练门店关系：`pt_coach_store_rel` 中教练 `1` 的门店为 `79,80,81,82,83,85`，不含 `87`。
- 当前预约门店：`82`，因此规则的商品/门店精确匹配无法命中。
- 影响：课时成本为 `¥0.00`，该记录进入报表异常或按零成本处理。
- 建议：业务确认规则应该绑定哪些门店后，再由管理员在页面修正规则；不要在测试阶段自动替换规则。

### P1：历史订单的销售归属教练快照为空

- `pt_private_order.coach_id` 已因 Flyway 补列，但旧测试订单值为 `NULL`。
- 预约完成使用 `pt_private_appointment.coach_id=1` 可以成功，但订单销售归属和后续整单提成口径仍缺快照。
- 建议：新订单创建链路必须写入唯一指定教练快照；历史数据是否补写需单独制定迁移规则。

### P2：预约列表没有“重置”按钮

- 其他私教列表多数提供“重置”；预约记录页面只有“搜索”。
- 筛选后只能手动清空输入框再搜索，容易让后台人员误以为条件仍然生效。

### P2：代约商品无权益时提示不够明确

- 教练、会员选择完成后商品下拉为“无数据”。
- 建议明确显示“该会员没有可用私教权益/课时已用完/商品不匹配”，降低运营人员排查成本。

### P2：菜单折叠时直接点击子菜单不生效

- 私教管理折叠时直接定位“预约记录”会超时；先展开“私教管理”后即可进入。
- 这是当前菜单交互约束，测试脚本和人工操作均需先展开父菜单。
